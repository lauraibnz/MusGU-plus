MusGU+ Evaluation: Stable Audio 3

The Music-Generative Usable+ AI (MusGU+) framework is a musician-centered evaluation framework designed to assess how generative music models can be adapted, used, and controlled in real-world creative contexts. The framework evaluates models along three complementary dimensions, with each dimension addressing a key question from the musician's perspective:

  • Adaptability — Can I realistically adapt this model to my own data?
  • Usability — Can I access, run, and integrate this model into my music-making workflow?
  • Controllability — Can I guide the model in musically meaningful and interpretable ways?

Musical applications

continuation, editing, text-to-music

Adaptability

30%

Hardware Requirements

✘ Not supported

Although LoRA fine-tuning is provided, the released models remain large, and the available materials do not demonstrate that adaptation can be performed on CPU-only systems or consumer-grade GPUs within a practical timeframe for end users.

Dataset Size

✘ Not supported

The official materials do not document that Stable Audio 3 can be effectively fine-tuned using small personal datasets, nor do they establish a moderate dataset requirement. Without evidence of feasible adaptation from musician-sized datasets, dataset requirements remain unsupported from a musician-centered perspective.

Adaptation Pathways

✔︎ Fully supported

The repository provides a dedicated LoRA fine-tuning workflow, including dataset preparation, training, checkpointing, and loading adapted LoRA checkpoints at inference time. Pretrained model checkpoints and autoencoders are also available.

Technical Barriers

✘ Not supported

Fine-tuning is performed through command-line tools and Python-based workflows. No graphical or notebook-based adaptation interface is provided, and users must configure the software environment, prepare data, and run training themselves.

Model Redistribution

~ Partially supported

The Stability AI Community License permits users to create and distribute derivative works, including LoRAs and fine-tuned models. However, commercial use of these adapted models is subject to licensing conditions, including an annual revenue threshold above which an Enterprise License may be required.

Usability

67%

Interface Availability

✔︎ Fully supported

Stable Audio 3 provides a publicly accessible Hugging Face Space with a graphical interface for text-to-audio generation. The repository also provides a local Gradio interface exposing additional generation and editing controls.

Access Restrictions

✔︎ Fully supported

Open-weight Stable Audio 3 models are available with pretrained checkpoints and inference code, allowing unrestricted repeated local inference without subscriptions, usage quotas, or time limits. Although the Large model is API-only, the Small and Medium models can be run locally.

Real-time Capabilities

~ Partially supported

Stable Audio 3 is optimized for very fast generation, with the released benchmarks reporting generation times of several seconds or less depending on model size, output duration, and hardware. However, it is not designed for continuous low-latency interaction or live musical control, and real-time-factor performance on modest hardware does not by itself constitute a live real-time system.

Workflow Integration

✘ Not supported

The released tools provide web, local Gradio, CLI, and Python inference workflows, but no direct integration with DAWs, visual programming environments, live coding systems, or dedicated music hardware is provided.

Output Licensing

~ Partially supported

Users may own, distribute, and commercialize generated outputs under the Stability AI Community License, but commercial use is subject to licensing conditions, including the annual revenue threshold for organizations using Stability AI models commercially.

Community Support

✔︎ Fully supported

A public Harmonai Discord server is provided for users, with discussions and weekly office hours focused on AI audio and music.

Controllability

25%

Conditioning Inputs

✘ Not supported

Stable Audio 3 conditions generation primarily through descriptive text prompts. Reference audio is used as source material for inpainting and continuation rather than as a separate musical conditioning modality for controlling attributes such as style, timbre, melody, or rhythm.

Time-Varying Control

~ Partially supported

Users can specify one or multiple temporal regions to regenerate through inpainting masks, while preserving the surrounding audio. This provides segment-level localized control, but not fine-grained control over musical attributes such as pitch, dynamics, rhythm, or structure over time.

Feature Disentanglement

✘ Not supported

The provided controls are not designed to independently manipulate distinct musical attributes. Text prompting and mask-based editing do not expose isolated controls for features such as timbre, pitch, rhythm, or structure.

Control Parameters

~ Partially supported

The released interface and inference workflow expose several configurable generation parameters, including duration, sampling steps, CFG scale, sampler, seed, and initialization noise level for audio editing. However, users are not given direct control over internal representations or musically interpretable latent dimensions.
